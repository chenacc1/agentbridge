# AgentBridge 软件功能情况与前端执行逻辑

## 1. 当前结论

AgentBridge 的核心软件功能已经开发完成：手机可以安全连接电脑上的 Bridge，先选择 Workspace，再查看、新建、恢复或继续 Agent 会话；二维码、流式消息、控制权、停止、审批和模型选择仍然可用。

这里的 Workspace 是电脑上已经登记的本地目录，不是 ChatGPT 云端 Project；“看到同样的项目”指 AgentBridge 已登记的目录和 Provider 通过公开接口提供的会话，不是镜像任意桌面软件的私有界面或数据库。

当前还有两项运行交付工作没有闭环：

1. 8787 端口仍运行旧版 Bridge，而且有一个 Codex 回合处于 running。为避免中断任务，尚未强制重启，因此新版工作区界面还没有装载到这个进程。
2. Tailscale 启动器已实现，但当前本机没有可用 tailnet IP，也没有在线手机 peer，仍需真实手机完成最后一次跨网扫码验收。

## 3. 四种网络模式的关系

四种模式只决定“手机怎样到达电脑”，不会改变 Workspace、会话、Agent 或二维码逻辑。

| 模式 | 手机到电脑的路径 | 手机是否安装额外 App | 适合场景 |
| --- | --- | --- | --- |
| LAN | 同一局域网直接访问电脑 IP | 否 | 同一 Wi-Fi |
| Tailscale | 私有 tailnet IP | 是 | 长期跨网络使用 |
| ZeroTier | 私有虚拟局域网 IP | 是 | Tailscale 不稳定或已有 ZeroTier |
| Cloudflare | 公网 HTTPS Tunnel | 否 | 手机不能安装 VPN 类 App |

Cloudflare 模式额外启用访问密钥。手机先把二维码中的密钥换成 HttpOnly gate cookie，再交换一次性配对码。电脑上的管理页仍从 `http://127.0.0.1:8787` 打开，因此本地登录 Cookie 不使用 Secure；手机侧 HTTPS 会话仍使用 Secure。

## 4. 后端执行结构

```text
手机浏览器
  ├─ HTTP：创建、发送、停止、审批、切换模型
  └─ SSE：接收状态、消息、工具事件和流式输出
        │
        ▼
AgentBridge Server
  ├─ PairingManager       设备配对、会话 Cookie、撤销
  ├─ WorkspaceCatalog     本地工作区登记与持久化
  ├─ ConversationCatalog  Bridge Session 索引与持久化
  ├─ SessionManager       控制租约、运行状态、惰性恢复
  ├─ EventStore           事件日志、游标和断线回放
  └─ AdapterRegistry
       ├─ Codex App Server
       ├─ Claude Code CLI
       ├─ DeepSeek Harness ACP
       ├─ DSH Desktop companion
       └─ ZCode native handoff
```

关键原则：

- 手机永远不提交任意电脑路径，只提交服务器已登记的 Workspace ID 或 alias。
- Provider 运行句柄只在内存中；重启后会话先显示 offline，发送消息时才恢复。
- 前端按钮不是安全边界。创建、停止、审批、模型切换都会在 SessionManager 再次检查能力、状态和控制权。
- Provider 历史发现必须由用户点击“同步历史”触发，页面加载不会自动启动 Codex App Server。

## 5. 前端启动执行逻辑

```text
init()
  │
  ├─ 1. 读取 URL 中的 Cloudflare access key
  │      └─ POST /api/access → 写入 gate cookie → 从地址栏移除 key
  │
  ├─ 2. 读取一次性 pairing code
  │      └─ POST /api/pairings/exchange → 写入设备 cookie → 从地址栏移除 code
  │
  ├─ 3. GET /api/state
  │      ├─ 手机未配对：提示重新扫码
  │      └─ 电脑 loopback：自动创建 Desktop browser 会话
  │
  ├─ 4. 恢复导航目标
  │      ├─ 二维码指定的会话
  │      ├─ 当前设备的 lastSessionId
  │      └─ 第一个 Workspace / 第一条本地会话
  │
  ├─ 5. renderState()
  │      └─ Workspace 列表 → 当前 Workspace 的 Session 列表 → 当前会话
  │
  └─ 6. EventSource(/api/events)
         └─ 按事件增量更新消息、状态、控制权和模型
```

## 6. 前端主要交互流程

### 6.1 切换 Workspace

1. 点击 Workspace 行。
2. 清空当前会话选择。
3. `resolveWorkspaceNavigation()` 从该 Workspace 选择第一条本地会话。
4. Session 列表只渲染属于这个 Workspace 的记录。
5. 新建表单自动切换为当前 Workspace。

### 6.2 同步历史

1. 前端只显示 capability 中 `discover=true` 且当前可用的适配器。
2. 用户点击“同步历史”。
3. 请求 `GET /api/conversations?workspaceId=...&adapterId=codex&refresh=1`。
4. CodexAdapter 用公开 `thread/list` 按规范化 cwd 分页读取。
5. ConversationCatalog 幂等合并，新增记录保持 offline，不立即恢复。
6. 前端刷新状态并选中合并后的会话。

### 6.3 新建会话

1. 适配器下拉框仅允许 `create=true` 的项目。
2. 提交 Workspace alias、适配器、标题和 commandId。
3. 服务端重新校验适配器能力与 Workspace allowlist。
4. 创建 Provider Conversation 和稳定 Bridge Session。
5. 返回 session.ready 后，前端进入该会话。

DSH Desktop 是 attach-only，不会出现在可创建列表；必须在桌面会话中执行 `/phone`。

### 6.4 发送消息

1. 前端检查当前不是 running，且本设备拥有控制权或当前无人控制。
2. `POST /api/sessions/:id/messages` 发送正文和幂等 commandId。
3. 离线会话先由 SessionManager 惰性 attach/resume。
4. EventStore 先记录用户消息和 turn.started。
5. Provider delta 被约 120ms 合并后通过 SSE 下发。
6. message.completed/turn.completed 到达后，页面恢复可输入状态。

### 6.5 停止、审批与模型

- 停止：第一次点击进入 5 秒确认状态；第二次请求 stop。服务端再次检查 cancel capability、active turn 和控制权。
- 审批：审批卡片提交 approvalId、decision 和 commandId；没有控制权或审批已结束时拒绝。
- 模型：选项只能来自 Provider 返回的 modelDirectory，不能输入任意模型字符串；运行中禁止切换。

### 6.6 SSE 重连

- 浏览器 EventSource 自动重连并携带 Last-Event-ID。
- 服务端只补发游标之后的事件。
- delta 通过 offset 合并，同一片段重复到达也不会重复显示。
- 前端以 80ms 节流渲染，避免长回复让手机卡顿。

## 7. 仍需实机验证的边界

1. 在电脑和手机登录同一个 Tailscale tailnet，确认手机使用蜂窝网络时可以扫码、打开 Workspace、发送消息并收到 SSE。
2. Codex、Claude、DSH Desktop 与 Harness 的真实会话仍依赖对应工具已安装、已登录并开放所需公开接口。
3. 当前定位仍是单机自用 Bridge；长期多用户公网服务需要更完整的账户授权、代理身份校验、日志加密与恢复机制。
